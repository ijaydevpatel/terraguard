# Ethics and data statement

Prepared for ENGE817. **Status: draft pending confirmation of the programme's ethics
requirements and deadline (tracker task T012).**

## What this project studies

Software artefacts and cloud configuration in a dedicated research account owned by the
researcher. The object of study is a prototype tool and the configurations it analyses.

## Human participants

None. No human participants are recruited, observed, surveyed or interviewed. No personal
data is collected, processed or stored.

One activity involves another person: an independent review of a sample of severity labels
and ambiguous policy cases (task T112), expected to be the supervisor or a peer. That is
expert review of the researcher's own labelling decisions, not data collection about a
participant. No personal information about the reviewer is recorded beyond the fact that a
review took place.

## Data

All experimental data is generated by the researcher in a dedicated AWS account. There is
no third-party, organisational or production data at any stage.

* Every credential-shaped value in the repository and datasets is the synthetic marker
  `TERRAGUARD_TEST_SECRET_nnn`.
* The AWS account id used in fixtures, `000000000000`, does not exist.
* Terraform state and plan files are never committed. A pre-commit hook and a CI step
  refuse them, and refuse any file containing an AWS access key id.
* Redaction runs on write, not at report time: the binary plan and raw plan JSON exist only
  inside a temporary directory and are deleted in a `finally` block.
* Published datasets contain categorised values and hashed references, not raw values.

## Risk to systems

Scenarios deliberately weaken security controls - opening a port, removing encryption,
stopping a trail. Three limits keep that contained:

1. every change is made in an isolated research account with no other resources;
2. the deliberately weakened resources hold no data beyond synthetic markers, and the
   public-access scenario changes the control without granting real read access;
3. `restore_baseline.py` returns the environment to the secure baseline and confirms zero
   drift before the next observation begins.

## Cost and environmental impact

The footprint is a security group, three small buckets, one IAM role and policy, and one
CloudTrail trail. No EC2, no RDS. Budget alarms at USD 5 and USD 15 are defined as code and
created on the first apply. Resources are destroyed at the end of every working session and
torn down completely at the end of the project.

## Honesty of reporting

* Actual hours are not recorded in the tracker, so no figure in it should be read as
  measured effort.
* No accuracy target is claimed in advance; metrics are reported as observed.
* Severity labels are subjective. The rubric (T111), the independent review (T112) and the
  disagreement log (T113) exist so that subjectivity is documented rather than hidden.
* Where evidence is missing, the tool reports `indeterminate` rather than compliance.
